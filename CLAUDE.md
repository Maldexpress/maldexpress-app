# Project brief for Claude Code

## What this is
Maldexpress: a marketplace + delivery app for the Maldives. Three portals in one app — customer (public browsing), business (store management), delivery (job pickup). Currently a single self-contained file, `index.html`, with inline CSS and vanilla JS. No build tooling, no framework, no npm dependencies yet.

## Current architecture (as of this file's writing)
- **Hosting**: GitHub Pages from `main` (root): https://maldexpress.github.io/maldexpress-app/ (not Render). Merging to `main` deploys.
- **State**: one global `state` object, re-rendered on every change via a hand-rolled `render()` dispatcher keyed on `state.role` and `state.screen`.
- **Data layer**: `DB` object (`businesses`, `items`, `orders`, `delivery`) synced to Supabase Postgres tables via `loadDB()` / `saveDB(part)`. `saveDB` currently does a full-array `upsert` per call rather than single-row writes — fine at this scale, but revisit if it grows.
- **Auth**: **Firebase Auth** (project `maldexpress`), email + password with email-link verification; `fbAuth` in index.html. Supabase only stores data: it is created with `accessToken` returning the signed-in Firebase user's ID token (third-party auth), so `sb.auth.*` is unavailable. Firebase tokens carry no Supabase `role` claim, so requests run as the `anon` role and every RLS policy / SQL function identifies the user with `public.app_uid()` (Firebase `sub`, only for this project's tokens with `email_verified`). User id columns are `text`, not uuid. Migration: `supabase/migrations/2026-11-08_firebase_auth.sql`. Edge functions verify Firebase tokens themselves (`create-order-payment`, deployed with JWT verification off). `state.authed / state.customerId / state.customerEmail` hold the session.
- **Styling**: "Bright lagoon" light theme (replaced the dark "Sea of Stars" glass, "Atoll", "Harbour signage" and the original glassmorphism). A Maldivian island in daylight: warm white-sand ground (`--sand-bg`), white cards with soft shadows (the class is still `.glass`), turquoise lagoon (`--lagoon-500`, alias `--plankton`) for what's selected or active, sunset coral (`--sunset`, alias `--night-coral`) for the order-moving action and prices. The home hero is a turquoise→ocean-blue banner with the logo mark (`BRAND_MARK_SVG`), wordmark, bell and menu/avatar. Fonts: Bricolage Grotesque for headings (`--display`), Plus Jakarta Sans for body. On phones the tab bar is docked white at the bottom and popups slide up as white sheets. On screens ≥1024px (PC) it becomes a website: a sticky white top navigation bar (logo left, sections right), wide content with multi-column product grids, and popups as centred dialogs. Colour tokens live in `:root`; old names (`--glass`, `--coral`, `--ink`, `--channel`, `--ground`, `--shallow`, …) are kept as aliases because inline styles in the script use them. Mobile-first, `--fs` CSS variable drives the user-adjustable font size (default 14px).
- **Delivery zone picker**: drawn as a ferry route (`zoneRouteHTML()` / `pickZone()`), stops in order Malé → Hulhumalé Phase 1 → Phase 2. A hidden input keeps the `#c_zone` / `#cao_zone` ids.
- **Sheets/modals**: bottom-sheet popups (`openSheet(name)` / `sheetHTML()`) handle all forms — signup, checkout, settings, etc.

## Business rules to preserve
- Free tier: 30 days from `joinDate`, max 10 items. Pro tier (MVR 500 one-time): max 500 items, no expiry.
- **Island-wise delivery** (`routeFor()` in index.html, `orders.route`): stores and riders each pick an atoll + island (`ATOLLS`). Greater Malé (Malé, Hulhumalé, Villimalé) → Greater Malé uses the zone fees below (`male_zone`). Greater Malé → any island goes by boat (`boat_to_island`); an island store can deliver on its own island (`local`) or send to Malé by boat (`boat_to_male`), but never to a different island (blocked at checkout). For every non-zone route the store sets the delivery charge when it approves (`approve_swipe_order(p_order_id, p_delivery_charge)`), which updates `delivery_fee`, `delivery_partner_payout` and `total`. Migration: `supabase/migrations/2026-11-08_islands.sql`.
- **Riders are island-wise**: a rider sees open jobs from stores on their own island (all of Greater Malé counts as one area), plus, while **online** with a GPS fix under 30 minutes old, jobs from stores within `NEARBY_KM` (20 km) of the store's saved location. New jobs alert inside the app (toast + vibrate + nav badge) on the 8 s live poll. Stores save their GPS location in Settings.
- Delivery fee is a **flat amount by zone**, not a percentage: Malé MVR 15, Hulhumalé Phase 1 MVR 20, Hulhumalé Phase 2 MVR 25. Chosen by the customer at checkout.
- **Buy now orders are paid only by Swipe** (cash on delivery and bank transfer were removed for them). Flow: customer places order (`payment_method 'swipe'`, `payment_status 'awaiting_approval'`) → store approves (`awaiting_swipe`) or declines → customer pays on a Swipe link created on the **store's own Swipe account** (edge function `create-order-payment`) → Swipe calls `swipe-order-webhook?business=<id>` → `paid`. A Swipe order can't go to a rider until it's paid, and riders never collect cash for it; the store owes the rider the zone fee after delivery.
- **Fees on Swipe orders**: Maldexpress takes 5% of the order total; Swipe's 1% charge is split 1:1 between the store and Maldexpress. So per order the store owes Maldexpress `5% − 0.5% = 4.5%` (`platform_fee_due`) and keeps 94.5%. Swipe has no split-payment API, so fees are tracked per order and settled by an admin (Admin → Fees). Rates live in `SWIPE_FEES` (index.html) and the webhook — keep them in sync.
- A store must connect its Swipe merchant account (client ID, client secret, webhook signing secret) before it can take orders. Credentials live in `business_swipe_accounts`, which has RLS with no policies so only edge functions can read them.
- **Rentals and auction wins** can be paid by Swipe (if the store has connected it), bank transfer, or cash **to the store** (`cash_on_pickup`). Riders never carry cash: the live `orders_insert_guard` / `orders_update_guard` triggers reject `pending_cash` for any method except `cash_on_pickup` (`cash_not_supported`). Swipe: a rental is inserted as `awaiting_swipe`; an auction win's `complete_auction_order` sets `awaiting_swipe` for `swipe`. Bank transfer: the customer uploads a slip whose amount and account number must match, and the store must approve it (`approve_order_payment`). Cash: the store marks it received. Swipe fees apply to these orders too.
- **The live database is ahead of this repo.** It has payment review / problem flags (`payment_review`, `flag_payment_problem`), store-set delivery charges (`set_delivery_charge`, `awaiting_delivery_charge`), checkout blocking for unpaid delivered orders (`customer_checkout_blocked`), and order guard triggers that were applied directly in Supabase. `supabase/live_functions_snapshot.sql` is a read-only snapshot (2026-11-08). Check it before replacing any live function.
- Stores and customers can contact each other at any point (Call / WhatsApp / Viber buttons via `contactHTML()`) on the store's order detail, booking cards, and the customer's order detail.
- Store account number/name are only shown to the customer/rider while payment is unconfirmed.

## Known follow-ups (not yet done)
1. **Split the single HTML file** into a real project structure (components/modules) once it grows further — it's still manageable as one file for now, but don't let it double again without restructuring.
2. **Slip uploads** are stored as base64 data URLs directly in the `orders.slip_url` column. Move to Supabase Storage once volume matters — cheaper and keeps table rows small.
3. **No business/delivery admin oversight** — e.g. no way to suspend a store, dispute a payment claim, or handle a customer complaint. Out of scope for MVP but worth flagging.
4. Payment for the Pro tier upgrade (`payForPro()`) is currently simulated client-side with no real payment gateway. Needs BML/real payment integration before launch.

## Conventions
- Keep everything mobile-first; this is meant to be used primarily on phones.
- Money is always Maldivian Rufiyaa (MVR); the `money()` helper formats it — don't hardcode currency strings elsewhere.
- Don't reintroduce `window.storage` or `localStorage`/`sessionStorage` for real data — Supabase is the single source of truth so the app works outside Claude's own preview environment.
